# GNSS Sim — имитатор сигналов L1 (GPS, Galileo, SBAS, QZSS)

Чистый Python (NumPy) генератор комплексной огибающей сигналов диапазона L1:
**GPS L1 C/A**, **GPS L1C**, **Galileo E1**, **SBAS L1 C/A** и **QZSS L1 C/A**.
Результат либо пишется в I/Q-файл, либо передаётся потоком на **USRP B210**
через UHD. Интерфейс — PyQt5 (как в SDR_Scan), есть CLI и карта OpenStreetMap
для построения маршрутов.

Реализация не использует C-код `gps-sdr-sim` / `multi-sdr-gps-sim` во время
работы: орбитальная модель, эфемериды, коды и модуляция портированы на Python
и проверены по ICD (IS-GPS-200 / IS-GPS-800 / IS-QZSS / Galileo OS SIS ICD).

## Что реализовано

| Сигнал | Состояние |
|---|---|
| GPS L1 C/A — BPSK(1), 1.023 Мчип/с, NAV (5 подкадров, чётность, TOW) | Полностью |
| GPS L1C — L1Cp TMBOC(6,1,4/33) + L1Cd BOC(1,1), 0.75/0.25 | Коды, L1Co и модуляция полностью |
| Galileo E1 — CBOC(6,1,1/11), E1-B (данные) + E1-C (пилот, вторичный код 25) | Полностью: реальный I/NAV 250 бит/с (FEC ½ K=7, интерливер 30×8, CRC-24Q, слова 1–6) |
| SBAS L1 C/A — PRN 120…158 | Полностью: DO-229 сообщения 250 бит/с (MT1/2-6/9/17/24/25/26/63, CRC-24Q) |
| QZSS L1 C/A — PRN 193…206 | Коды и NAV полностью |
| CNAV-2 (данные L1Cd) | Пока заглушка; FEC — в разработке |

Коды сверяются с таблицами ICD: C/A (в т.ч. SBAS/QZSS) — по «первым 10 чипам»;
L1Cp/L1Cd/L1Co — по «первым/последним 24 чипам» (self-tests).

## Повторное использование готового IQ-файла

Вместо генерации можно взять уже готовый IQ-файл (полезно для повторной
передачи записанного сигнала):

```powershell
# CLI: генерация пропускается, файл читается и (при --tx) идёт в эфир
... -m gnss_sim --iq-input out.cs16 --tx --tx-gain -20
# Без --tx файл только проверяется и описывается в журнале
... -m gnss_sim --iq-input out.cs16
# Читать файл целиком в RAM и зацикливать из памяти (быстрее, нужен объём RAM)
... -m gnss_sim --iq-input out.cs16 --iq-ram --tx --tx-gain -20
```

`gnss_sim/iqfile.py::IqFileSource` читает `cf32`/`cs16`/`cs8`/`cs4`, при этом
формат, `sample_rate`, `center_freq` и `output_scale` берутся из side-car
`<файл>.json` (если он есть); иначе используются значения из настроек и
пишется предупреждение. При включённой передаче файл проигрывается по кругу
(возврат к началу файла на диске), длительность/`--no-loop` учитываются.
Флаг `--iq-ram` (в GUI — галочка **«Загрузить IQ в RAM (зацикливать из
памяти)»** рядом с «Использовать готовый IQ-файл») читает файл целиком в
оперативную память и зацикливает из неё; доступная RAM проверяется через
`sysinfo`, и при нехватке выводится понятная ошибка (обойти можно, сняв
галочку). По умолчанию — потоковое чтение с диска; в журнал пишется, откуда
идёт воспроизведение (RAM или диск). RINEX/`SignalEngine` при этом не
используются.

## RINEX-эфемериды

Если файл не задан (или включено автоскачивание), имитатор сам загружает
дневной мульти-GNSS broadcast-файл `BRDC00IGS_R_YYYYDOY0000_01D_MN.rnx.gz`
с BKG (основной) или CDDIS (резерв), распаковывает и кэширует в
`rinex_cache/`. Файлы появляются с задержкой ~1 сутки, поэтому пробуются и
предыдущие дни. Поддерживаются системы G (GPS), E (Galileo), J (QZSS),
S (SBAS); RINEX 2 и 3.

**Тип файла важен:** `brdc{doy}0.{yy}n` (`.26n`) — **только GPS**;
`brdc{doy}0.{yy}g` (`.26g`) — **только GLONASS**; merged
`BRDC00IGS_R_…_MN.rnx` — мульти-GNSS (G/E/J/C, предпочтительный). Для
Galileo/BeiDou нужен merged-файл (или посистемный набор `l`/`c`/`j` — см.
ниже); при выборе per-system файла в журнал
пишется «только GPS …». Архивы `.gz` распаковываются прозрачно (детект по
магии `1f 8b` и по расширению), распакованная копия кладётся рядом
(`foo.26n.gz` → `foo.26n`); выбранный файл всегда сопровождается в журнале
списком систем (счёт G/E/J/C).

### Скачивание с CDDIS (логин/пароль, выбор даты)

CDDIS (Earthdata) требует авторизации. Дневные файлы лежат по адресу
`https://cddis.nasa.gov/archive/gnss/data/daily/{yyyy}/brdc/` (без папки DOY):

* `BRDC00IGS_R_{yyyy}{doy:03d}0000_01D_MN.rnx.gz` — мульти-GNSS;
* `brdc{doy:03d}0.{yy:02d}n.gz` — GPS RINEX 2;
* `brdc{doy:03d}0.{yy:02d}g.gz` — ГЛОНАСС RINEX 2;
* `brdc{doy:03d}0.{yy:02d}l.gz` / `.c.gz` / `.j.gz` — Galileo / BeiDou / QZSS.

**Мультисистемный `BRDC00IGS_R_…_MN.rnx` публикуется только за прошедшие
сутки.** Поэтому для текущей даты (UTC) merged обычно отдаёт 404, и программа
берёт посистемный набор `brdc{DOY}0.{yy}{n,g,l,c,j}`: скачивает все уже
выложенные файлы, распаковывает их в `rinex_cache/` и парсит вместе
(`parse_nav_file` принимает список путей и объединяет эфемериды). 404-ответы
считаются и логируются один раз, а не по каждому URL. В GUI над кнопкой
«Скачать за дату» есть заметка об этом; в журнал пишется понятное сообщение,
например `CDDIS: мультисистемный BRDC00IGS доступен только за прошедшие
сутки; для текущей даты берём посистемные brdc{DOY}0.{yy}{n,g,l,c,j}`.
Например, для 2026-09-21 (DOY 264): `brdc2640.26n.gz`, `brdc2640.26g.gz`.

Скачивание идёт через `urllib` с cookie-jar и HTTP Basic (редирект на
`urs.earthdata.nasa.gov` и обратно); можно вместо логина/пароля указать
bearer-токен. `.gz` распаковывается в `rinex_cache/`.

CLI:

```powershell
# Скачать за конкретную дату (source=cddis) с логином/паролем Earthdata
... -m gnss_sim --source cddis --cddis-user МОЙ_ЛОГИН ^
    --cddis-password ПАРОЛЬ -t "2026/09/21,00:00:00" -d 60 -o out.cs16

# Или по bearer-токену
... -m gnss_sim --source cddis --cddis-token ТОКЕН ...

# Источник: auto (по умолчанию, BKG + CDDIS при наличии данных входа),
# bkg — только BKG, cddis — только CDDIS
... -m gnss_sim --source bkg -t "2026/09/21,00:00:00" -d 60
```

GUI (группа **«Эфемериды и позиция»**): список «Источник эфемерид»
(`auto`/`bkg`/`cddis`), поля **CDDIS логин**, **CDDIS пароль** (скрытый), **CDDIS
токен** (необязательно), поле **Дата CDDIS** (`YYYY/MM/DD`, подставляется из
времени старта) и кнопка **«Скачать за дату»**: дата превращается в DOY,
загрузка идёт в фоновом потоке, а готовый файл подставляется в «RINEX
navigation».

### Спектр (PSD)

Вкладка **«Спектр»** показывает спектральную плотность мощности (метод Уэлча,
окно Ханна, 50 % перекрытия — `gnss_sim.power.welch_psd`, чистый NumPy без
SciPy) на осях «частота, МГц» / «PSD, dBFS». Во время генерации обновляется
кривая **TX** (блок ≤65536 отсчётов примерно раз в 0.5 с); при включённой
галочке «Слушать RX» добавляется кривая **RX**. График строится на
`pyqtgraph` (`gnss_sim/spectrum.py`) и работает в offscreen-режиме (тесты без
дисплея).

### Приёмник u-blox ZED-F9P (COM)

Группа **«Приёмник u-blox (COM)»** на вкладке «Генерация» читает NMEA с
ZED-F9P по COM-порту (`gnss_sim/ublox.py`, pyserial). Выберите порт (список
из `list_ports`, по умолчанию `COM3`) и скорость (9600/38400/115200/460800,
по умолчанию 38400), нажмите **«Подключить»**. Раз в 0.5 с обновляются строка
состояния (lat/lon/высота, UTC, fix, число спутников, HDOP) и таблица видимых
спутников (система, PRN, элевация, азимут, SNR). Кнопки **«Взять позицию из
приёмника»** и **«Взять время из приёмника»** подставляют координаты в
`Широта/Долгота/Высота`, а время — в «Время старта». Если COM-порта нет,
приложение выводит сообщение и продолжает работать.

## Модель самосвала

Рейс по замкнутому маршруту (haul cycle): гружёный ход со скоростью
`v_laden`, разгрузка, порожний возврат со скоростью `v_empty`, погрузка; далее
повтор `cycles` раз. Скорость на поворотах ограничивается из радиуса
кривизны и бокового ускорения, есть ограничение разгона/торможения и тормозной
«просмотр» вперёд до остановки у конца плеча. Высота меняется линейно по
заданному уклону (`grade_pct`). Motion-файл — `lat;lon;h` на 10 Гц, совместим
с `motion.py`.

## Безопасность при передаче

Передача на частоте GPS без экранирования запрещена. Соединяйте TX B210 с
приёмником через **аттенюатор 50–60 дБ и DC block**, либо используйте
кабельное подключение в экранированной лаборатории. Ответственность за
соблюдение местных норм — на операторе.

## Мониторинг RX, регулятор мощности и эхо в камере

При передаче на B210 можно **одновременно принимать** сигнал на другом
канале — контролировать собственный TX, измерять уровень и SNR, автоматически
подбирать усиление и оценивать эхо/многолучёвость (например, в безэховой
камере). Реализация: `power.py` (чистый NumPy: `rms_dbfs`, `PowerRegulator`,
`delay_profile`, `estimate_noise_floor`) и `uhd_duplex.py` (ленивый `import
uhd`).

### Физика B210: порты и гетеродины

B210 = один AD9361 с **раздельными LO приёма и передачи**: RX и TX могут
работать одновременно и на разных частотах (FDD). Важные ограничения:

* у канала 0 порт `TX/RX` один (TDD-переключатель) — **нельзя слушать свой
  TX на том же канале/порту**;
* для контроля передачи: **TX на `tx_channel` (порт `TX/RX`)**, **RX на
  другом канале (порт `RX2`)** через кабель/ответвитель или антенну;
* один RX LO общий для обоих RX-каналов, один TX LO — для обоих TX-каналов;
* одноимённые TX и RX каналы запрещены (программа выдаст понятную ошибку).

### Замкнутый контур мощности

Регулятор (`PowerRegulator`) измеряет уровень RX и подстраивает `tx_gain`
ограниченным пропорциональным шагом с EMA-сглаживанием и мёртвой зоной, чтобы
не раскачиваться. Шумовой пол измеряется один раз перед стартом передачи (TX
ещё выключен); SNR = уровень RX − шумовой пол. Шкала dBFS: комплексный тон
амплитуды 1.0 = 0 dBFS (как в SDR_Scan).

### Запуск (CLI)

```powershell
# TX на канале 0 (TX/RX), RX на канале 1 (RX2), авторегулятор до -30 dBFS,
# профиль задержек (топ-3 эхо) — ОБЯЗАТЕЛЬНО аттенюатор 50-60 дБ + DC block!
E:\MySoftware\SDR_Scan\.venv\Scripts\python.exe -m gnss_sim ^
    --tx --monitor --tx-channel 0 --tx-gain -20 ^
    --rx-channel 1 --rx-ant RX2 --rx-gain 30 ^
    --tx-power-target -30 --echo ^
    -t "2022/01/01,00:00:00" -d 600

# Только измерение, без автоподстройки; RX в стороне от TX (шумовой пол)
... -m gnss_sim --tx --monitor --no-tx-power-auto --rx-freq 1570e6

# Обычная передача без мониторинга (поведение не изменилось)
... -m gnss_sim --tx --tx-gain -20
```

В журнал раз в ~0.5 с пишется строка вида
`RX: -29.7 dBFS, шум -105.2 dBFS, SNR 75.5 дБ`. При включённом эхо-анализе:
`Эхо, топ-3: 0 нс / 0.0 дБ, 348 нс / -6.1 дБ, 1210 нс / -12.4 дБ`.

### GUI

Группа **«Мониторинг RX / мощность»**: галочка `cb_monitor` (слушать RX на
другом канале), цель `sp_target` (dBFS), `cb_auto` (авторегулятор TX gain),
`sp_rx_ch` (0…1), `ed_rx_ant` (порт, по умолчанию `RX2`), `sp_rx_gain`,
`sp_rx_freq` (0 = как TX) и `cb_echo` (профиль задержек).

### Безопасность

Контрольный RX-вход подключайте **только через аттенюатор 50–60 дБ** (и DC
block): без него мощность TX перегрузит вход приёмника. При работе «в
камеру» используйте экранированный объём и минимально возможное усиление.

## Производительность и CUDA

Синтез отсчётов можно выполнять на CPU (NumPy) или на GPU (CUDA через CuPy).
Бэкенд выбирается автоматически: если найден GPU NVIDIA и установлен
`cupy-cuda12x`, используется CUDA, иначе CPU. Явный выбор — `--backend
auto|cpu|cuda` в CLI или список «Бэкенд синтеза» в GUI.

Замеры при `fs = 2.6 МГц`, 27 каналов (GPS + Galileo + QZSS + SBAS),
старт Tokyo 2022/01/01:

| Бэкенд | Скорость | 6000 с файла | Размер (`cs16`) |
|---|---|---|---|
| CPU (NumPy, `complex128`) | ≈0.13× реального времени | ≈13 ч | 62.4 ГБ |
| CUDA (RTX 4080, блок 500 мс, `complex64`) | ≈9–17× реального времени | ≈10–15 мин | 62.4 ГБ |

CUDA использует `complex64`/`float32`; отличие от CPU-тракта `complex128`
по нормированной корреляции ≈0.999, что для имитации сигнала несущественно.
Для длинных файлов всё упирается в диск: при 2.6 Мвыб/с `cs16` = 10.4 МБ/с
(6000 с ≈ 62 ГБ), `cs8` = 5.2 МБ/с. Рекомендуемый размер блока генерации —
500 мс; ожидаемый размер файла печатается в журнал перед записью.

## RAM, длительность и зацикливание

Длинная запись (до 6000 с) упирается и в объём, и в пропускную способность
диска, поэтому есть режим **зацикливания (включён по умолчанию)**:

- приложение анализирует RAM (всего/доступно) и задаёт бюджет — 60 % доступной
  памяти или значение «Бюджет RAM», ГБ;
- считается, сколько секунд сигнала в этот бюджет влезает (для `cs16` при
  `fs = 2.6 МГц` это ≈10.4 МБ/с);
- автоматическая длина сегмента = `min(длительность, что влезает в RAM)`.
  Если заданная длительность **помещается** — генерируется ровно она (один
  сегмент), даже при включённом зацикливании; урезание (с предупреждением)
  происходит только при нехватке RAM, и тогда длина округляется вниз до
  кратного 30/18 с (90 с), как раньше;
- в файл пишется только сегмент; при передаче на B210 сегмент проигрывается
  из RAM по кругу (диск не нужен); для готового IQ-файла зацикливание —
  это seek в начало файла на диске. В журнал пишется, RAM это или диск;
- проверка «Стоп» выполняется не реже, чем раз в блок генерации
  (`--block-ms`), поэтому остановка срабатывает быстро;
- перед записью в журнал выводятся: доступная RAM, бюджет, максимум секунд,
  свободное место на диске и ожидаемый размер.

Параметры: `--loop-seconds` (0 = авто), `--memory-budget` (ГБ, 0 = 60 % RAM),
`--no-loop` (полная запись без зацикливания); в GUI — галочка «Зацикливать
сегмент (RAM)», «Длина сегмента», «Бюджет RAM» и строка состояния RAM.
Для длинной записи предпочтителен **RAM-диск** (например, ImDisk/OSFMount на
Windows или `/dev/shm` на Linux): путь к нему просто указывается в поле файла,
а приложение проверяет его свободное место.

При стыке сегментов возможен скачок фазы несущей (разные доплеры у разных
спутников не дают строго периодического сигнала) — приёмник обычно
удерживает захват; при необходимости уменьшайте `--loop-seconds`.

## Полоса и авто-подбор под BeiDou B1I

BeiDou B1I передаётся на 1561.098 МГц — это на 14.322 МГц ниже центра L1
(1575.42 МГц), поэтому в узкой полосе вокруг L1 он не помещается и движок
отбрасывает каналы B1I (`abs(f_offset) > fs/2 - 1.5 МГц`). Чтобы генерировать
B1I вместе с L1/E1, программа умеет автоматически подобрать центр и частоту
дискретизации: **центр 1568 МГц, fs 30 Мвыб/с** (значения проверяются по
лимитам B210: `fs <= 56 Мвыб/с`, `70 МГц <= центр <= 6 ГГц`).

Логика включается только когда B1I включён **и** текущие fs/центр его не
вмещают; если B1I выключен или уже помещается, ничего не меняется (выход
остаётся прежним). В журнал пишется, что было выбрано и сколько каналов B1I
сохранено. Отключить автоподбор можно флагом `--no-auto-b1i` (CLI) или
галочкой **«Авто-подбор fs/центра под B1I»** (по умолчанию включена, вкладка
«Дополнительные») — тогда ручные значения остаются, а B1I пропускается с
предупреждением.
