ПРОБЛЕМА 1: pip install падает на numpy (Python 3.13)
-----------------------------------------------------
Симптом: `pip install -r requirements.txt` -> numpy 1.26.4 уходит в source
build (Meson) и падает 'Unknown compiler(s): ...' (нет C-компилятора).
Причина: pin 'numpy>=1.24,<2.0' не имеет wheel'ов под py3.13 (NumPy 1.26.4
поддерживает <=3.12), pip уходит в сборку.
Решение: маркеры по версии Python.
- requirements.txt:
    numpy>=1.24,<2.0; python_version < "3.13"
    numpy>=2.0,<3.0; python_version >= "3.13"
- pyproject.toml: те же условия (одинарные кавычки).
Проверка: gnss_sim НЕ использует удалённые в NumPy 2 API (np.float_/np.int_/
np.trapz/np.in1d и т.п.); на 3.13 (numpy 2.5.3) `import gnss_sim` работает.

PYTEST в зависимости
--------------------
Было: setup_windows.ps1 предлагал `python -m pytest tests -q`, но pytest не
был в requirements. Добавлено 'pytest>=7.0' в requirements.txt и extra 'dev'
в pyproject.toml.

ПРОБЛЕМА 4 (ГЛАВНАЯ): CuPy не грузит nvrtc64_120_0.dll
------------------------------------------------------
Симптом: после `setup_windows.ps1 -Cuda` и запуска GUI появлялся диалог
'CuPy failed to load nvrtc64_120_0.dll: FileNotFoundError: Could not find
module ... (or one of its dependencies)'.
Причина: колесо cupy-cuda12x НЕ содержит CUDA runtime. CuPy ищет CUDA по
CUDA_PATH / nvcc on PATH / /usr/local/cuda (cupy/_environment.py:
_get_cuda_path); _setup_win32_dll_directory добавляет только <CUDA_PATH>/bin
и cupy/.data/lib. На машине нет CUDA Toolkit, CUDA_PATH пуст. NVIDIA-колёса
nvidia-*-cu12 кладут DLL в site-packages/nvidia/<comp>/bin, но НЕ регистрируют
их в DLL-поиске Windows -> nvrtc не найден, JIT-ядра не компилируются.
Решение (реализовано):
1. Новый gnss_sim/cuda_env.py -> configure_cuda_dlls(): на win32 находит все
   site-packages/nvidia/*/bin, вызывает os.add_dll_directory(...) для каждого,
   добавляет их в PATH и, если CUDA_PATH не задан, выставляет его в каталог с
   cudart64_*.dll. Off-Windows и без nvidia-пакетов — no-op.
2. gnss_sim/engine.py: вызов configure_cuda_dlls() ПЕРЕД `import cupy`.
3. setup_windows.ps1 -Cuda: кроме cupy-cuda12x<14 ставит
   nvidia-cuda-runtime-cu12 nvidia-cuda-nvrtc-cu12 nvidia-nvjitlink-cu12.
4. pyproject.toml extra 'cuda' теперь включает эти 3 nvidia-пакета.
5. requirements.txt / README.md: команды установки обновлены.
Проверка (воспроизводимо):
  .venv\Scripts\python.exe -c "from gnss_sim.engine import cuda_available; print(cuda_available())"
  -> True (CUDA_PATH изначально None, выставляется самим cuda_env)
  cupy JIT (cp.sqrt) компилируется.
  pytest tests/test_galileo_nav.py::test_engine_cpu_vs_cuda tests/test_cnav2.py::test_engine_cnav2_cpu_vs_cuda -q -> 2 passed

ПРОБЛЕМА 5: запуск плеера на удалённом Linux по SSH (фоновый режим)
------------------------------------------------------------------
Контекст: плеер — это штатный CLI-режим playback готового IQ-файла на USRP:
    python -m gnss_sim --iq-input FILE --tx [--uhd-args type=b200 --tx-gain ...]
(см. README.md ~стр. 274-275, 302-305). Нативный C++ помощник
(native/tx_player.cpp) собран ТОЛЬКО под Windows/MSVC (windows.h,
SetPriorityClass), поэтому на Linux используется Python-путь UHD
(gnss_sim/uhd_tx.py), а --tx-native там недоступен.
Проблема: при запуске по SSH процесс получает SIGHUP и умирает при закрытии
сессии — передача обрывается.
Решение: скрипт scripts/run_player_bg.sh — запускает плеер в фоне через
nohup (unSIGHUP), уводит stdin/stdout/stderr из терминала в лог, пишет
PID-файл. Подкоманды:
    scripts/run_player_bg.sh start  IQ.cs16 [арг. gnss_sim ...]
    scripts/run_player_bg.sh stop
    scripts/run_player_bg.sh restart IQ.cs16 [арг. ...]
    scripts/run_player_bg.sh status        # ps по PID + путь лога
    scripts/run_player_bg.sh log [N]       # хвост лога, по умолч. 40 строк
Примеры:
    scripts/run_player_bg.sh start out.cs16 --uhd-args type=b200 --tx-gain 18
    scripts/run_player_bg.sh start out.cs16 --uhd-args type=b200,serial=XXXX
    scripts/run_player_bg.sh log 100
    scripts/run_player_bg.sh stop
Переменные окружения: PYTHON (по умолч. .venv/bin/python, иначе python3),
GNSS_BG_LOG (по умолч. <repo>/player.log), GNSS_BG_PID
(по умолч. <repo>/player.pid), GNSS_BG_EXTRA (доп. аргументы строкой).
Особенности: по умолчанию плеер зациклен (актуально для фона; --no-loop
отключает); фиксирует $! после nohup (nohup exec'ает python — PID точный).
Проверка: `bash -n scripts/run_player_bg.sh` (Git Bash на Windows) — синтаксис OK.
На Linux сделать исполняемым: `chmod +x scripts/run_player_bg.sh`.
СТАТУС: скрипт создан, но НЕ закоммичен (untracked).
